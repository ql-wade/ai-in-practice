# 本地视频生成与剪辑

默认交付真正发生动作、有铺垫和结果、角色与画风可信的短片。把技术可播放、单镜视觉与运动、整片组接、故事和声音分开验收；只解码成功不能称为验收成片。

开工先确认所需 references 与 assets 已随技能完整到达执行环境；缺件时从正式技能包补齐并重验，不把只有主文当完整技能。无法取得时明确缺项，不声称已执行其中检查。

机械通过、单镜通过、整片组接通过是三个独立门槛；只有组接通过后保留的干净区间才计净可用时长。逐帧检查、技术指标、实际正常速度观看和真实听音分别记录，不能用其中一项替代另一项。任一关键项未验证或未通过，交付称为预览/待修订。

## 按需读取

- 交付前逐项读 [成片验收](references/acceptance.md)，并检视最终导出而不是只看原始片段。
- 涉及场景空间规则、运镜控制、短样扩长或连续接续时读 [历史案例与诊断](references/observed-case.md)；其中的设备、模型和结果是观察记录，不是通用保证。
- 涉及原文件校验、跨环境传输、版本交接或公开经验整理时读 [传输与恢复](references/transfer-and-recovery.md)。
- 参考文档或素材缺件时先停止相应检查，补齐并重新验证；不要用记忆或界面截图替代缺失的正式内容。

## 1. 锁定创作目标与可用环境

- 从需求中提取角色、场景、画风、笑点或情绪、时长、比例、字幕与声音要求。保留用户已经选定的组合，缺少关键决定才询问，不悄悄替换角色或风格。
- 先写简短分镜和每镜契约：原始参考、视觉摆位、可见动作、结果、拟用秒数，以及镜间是有意切镜还是连续接续。将关键结构、材质和空间关系写进场景母版；探索顺序是当前方案，不是所有片子的固定模板。
- 先确认实际执行环境，再做最小检查：操作系统、GPU/显存、可用磁盘、ComfyUI 服务或队列、模型和输入目录。不要从某个工具缺失推断另一台用户设备不可用。
- 分开验证云端或原生文件读取、Windows 执行和跨环境原文件传输。复用已批准的安装、模型和运行任务；不重复下载或启动同一作业，也不为本任务修改其他项目的原环境。新安装、付费服务、发布和额外插件不是默认授权。

## 2. 生成或导入原始参考图

- 用用户明确选定的人物与风格诚实描述，生成或读取参考图后，先检查脸、服装、构图、手和关键道具。
- 工具若返回原因不明的审核错误，如实报告范围；不可据此声称整类内容禁止，也不可用伪装或隐去身份的描述规避限制。只在允许范围内采用透明、实质性修订。
- 将原始图像字节保存到用户有权使用的原生文件存储，再通过受支持的文件物化方式传至执行环境；不要拿页面截图代替原图。
- 验证源与落地文件的 SHA-256、尺寸和格式，再复制入 ComfyUI 输入目录。传输失败时读 [传输与恢复](references/transfer-and-recovery.md)，不要使用安全绕过或分块编码技巧。

## 3. 先短样片，再逐镜生成

- 读取实际可用节点与模型，选择适合显存的 Wan I2V 工作流，不臆造节点名、参数或通用性能保证。涉及运镜或控制信号时，连同正负提示、节点输入和输出视频一起核对，详见 [历史案例与诊断](references/observed-case.md)。
- 先生成一段短样片，立刻对照原图查看首、中、尾帧、动作转折密集帧和实际运动，确认身份、风格与动作可用后才扩展。默认每镜从原始参考或经核验的原始参考衍生图独立生成；不要把已经漂移的尾帧不断串成更长视频。
- 短样通过不自动批准长版。帧数或时长扩展须有限试验，保留已通过短样和配置/哈希，写清延长假设、允许新增成本、全区间失败判据与回退点；重新检查完整保留区间和实际相邻镜组接。长版失败不能继承短样的 pass，精确裁掉坏尾后仍须重验保留的完整区间。
- 为每次提交保存检查点：执行环境、源图引用与哈希、workflow、prompt ID、种子、模型/量化/版本、提示词、原生尺寸、帧数/FPS、状态、输出位置和验收结论。重连先查队列、历史与输出，避免重复作业。
- 失败时定位到具体镜头、时间点和原因，只重做必要片段。遵守既定重试预算；无改善就回退或改镜头设计，不反复盲重试更长版本。停止依赖不合格素材的后续生成；需要超出授权的资源时先询问。

## 4. 剪辑为可读的故事

- 按镜头的信息/情绪功能选择片段。叙事片通常是铺垫 → 动作/冲突 → 结果/笑点；空间探索片先按当前场景方案核对发现、接近、进入、退出或远望等功能，不为时长插入未验重复镜头。裁切停滞和重复，统一比例与 FPS 后拼接；按实际需要使用干净切镜或短过渡。
- 分开呈现候选池总量、实际选用 EDL、组接已验净时长和生成中计划。单镜通过但未进入时间线，或未通过相邻组接，只算候选，不算净交付。使用零基、尾帧排除的 in/out；重叠转场扣除重叠。替换净增是新选用时长减被移除时长再减新增重叠，不把替换段全长当补足。保留 source、hash、版本轨迹和拒收清单，不重新引入失败版本。
- 约一分钟是近似创作目标，不是逐帧硬门槛。在用户未设严格下限时，不为接近边界的一帧差异重生成，也不靠慢放、冻结、重复或无意义补帧凑长。只有组接已验的保留区间才计入总时长。
- 保留角色和动作因果，不通过裁脸、遮挡或字幕掩盖变脸。字幕按节拍出现，检查中文字体、断行、安全边距、阅读时间和遮挡；字幕不能替没有发生的动作编故事。
- 字幕与 AI 标识按用户和目标平台要求处理。默认不自行添加角标，也不擅自去除原生来源信息；若需要带标识的交付版，核对当前有效要求，并从干净母版另出版本。用户要求去掉后期自加角标时，优先交付加角标前原始母版，不裁切、不修补、不重新生成，也不为去字重新编码。
- 只使用用户要求且有权使用的配乐、音效或声音。角色对白不能用字幕加笑声代替；不得默认克隆真人声音或使用未授权音乐。音频先锁定台词和时间线，后按实际画面写 cue，分轨混音并检查完整导出的听感；不能试听就明确未验收。未做口型同步不能声称 lip-sync。
- 常规交付可选兼容的 MP4/H.264、yuv420p、AAC 和 fast-start，仍以目标平台与用户要求为准。如做放大，分别报告生成原生分辨率和交付分辨率。

## 5. 验收与交付

交付前逐项使用 [成片验收](references/acceptance.md)，检视最终导出而不是只检视原始片段。

- 技术：可解码、容器/编码兼容、时间/尺寸/FPS 正确、音视频轨时长和同步合理；有声音要求时检查有效声长、整体响度、峰值或 true peak，AAC 轨存在或波形非零不能单独证明声音合格。
- 视觉：逐镜首/中/尾帧、动作转折密集帧和所有拼接边界对照原图，检查身份、服装、画风、手/肢体、道具、物理与连续性。任何后段变脸仍判身份未通过，即使最终裁掉该脸或被字幕遮住；合理视差也不能误判为主体变形。
- 故事与感知：动作真正发生，角色目标与反应清晰，有可见结果；逐帧、指标、正常速度观看和真实听音分别标为通过/待修订/未验证。没有受支持的播放或听音路径时，不能编造已看或已听；必要时请用户按标出的切点、空间运动、音量和音画同步完成最小人工确认。

交付前核对当前渠道的附件大小、编码和可打开条件。保留原始母版；需要压缩时先尝试保留原尺寸的兼容版，再按需另出缩小聊天版。分别报告原生与派生尺寸、帧率、帧数、时长和文件大小，不把聊天缩小版冒充母版或原尺寸文件，不把低分辨率文件冒充 4K。将最终 MP4 通过受支持的文件附件或用户指定的公开渠道交付，不以截图、私有下载 URL 或只存在本机的路径替代。任一关键项未通过，明确叫“预览/待修订”，不能叫“验收成片”。

本公开副本不包含私有 Library/Space 链接、文件 ID、账号资料、内部会话材料或电脑专属绝对路径，也不提供绕过安全限制、获取登录态或分块上传的技巧。遇到未知的 403 或权限结果，只记录该次请求的范围，不把它泛化为系统结论。
