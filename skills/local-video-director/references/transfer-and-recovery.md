# 传输与恢复

[返回技能](../SKILL.md)

这份参考文档描述原文件如何被核验和搬运，以及怎样把版本、检查结果和公开经验安全交接；不替代具体平台的权限或文件保存说明。

## 推荐顺序

1. 保留原始图像的字节副本，不用页面截图替代原图。
2. 在源端记录格式、像素尺寸和 SHA-256；传输完成后在落地端重新计算并比对。
3. 在复制到 ComfyUI 输入目录前，先打开落地文件检查可读性、方向、颜色、脸、手和关键道具。
4. 记录源引用、落地位置、哈希、尺寸、格式、传输方式和结果。公开记录只保留通用描述，不公开私有文件链接、文件 ID 或机器专属绝对路径。
5. 任何哈希或尺寸不一致都停止后续生成，先恢复文件传输，不要用压缩截图或重新编码“凑一致”。

## Windows 与跨环境边界

Windows 文件保存程序若因 os.setxattr 报错，先记录具体错误和已完成的范围。已有同机 WSL 2 Ubuntu 22.04 时，可以按其官方、未修改的文件流程，在 ext 持久目录保留元数据后再复制到 Windows 目标盘；这只是一次观察到的恢复路径，不代表 Windows 不可控，也不代表必须网页登录。

不要为解决传输问题关闭安全检查、伪造元数据、绕过登录或使用 base64 分块技巧。若源端、执行端或复制端的权限不同，分别确认哪一段失败，再选择用户有权使用的受支持文件通道。

## 技能完整性与版本交接

- 开工先确认所需 references 与 assets 已随技能完整到达执行环境；缺件时从正式技能包补齐并重验。无法取得时明确缺项，不把只有主文当完整技能。
- 分开记录候选池总量、实际选用 EDL、组接已验净时长和生成中计划；保留 source、hash、零基尾帧排除的 in/out、保留帧数、版本轨迹和拒收清单。单镜通过但未进时间线或未过相邻组接时，只算候选；替换净增要扣除被移除区间和新增重叠。
- 交接时写清执行环境、模型/量化/节点版本、输入哈希、workflow、种子、提示词、原生尺寸、帧数/FPS、输出位置、状态、失败范围、恢复动作和验收结论。不要把配置目标、局部测试或计划中的生成写成实际完成。
- 最终导出和聊天派生版分开保存与报告。交接前核对当前渠道的附件大小、编码和可打开条件；保留原始母版，原尺寸兼容副本与缩小聊天副本不是同一交付层级。

## 经验整理与公开边界

- 用户要求整理踩坑经验，可以整理去敏事实和可复用方法作为发布素材；这不等于公开发布授权，也不自动授权公开原视频、私人设备路径、任务标识或内部日志。
- 上传与发布分别按当时有效权限处理，不把个人权限规则固化进技能。只记录实际做过的检查和修复；未知状态先读回，不因一次重试成功就删除失败记录。

## 复现记录字段

```
source_reference: <公开记录使用的非私有描述>
source_sha256: <值或“未公开”>
source_dimensions: <宽x高>
format: <格式>
transfer_method: <受支持的文件通道>
destination_check: <哈希/尺寸/可读性结果>
candidate_total: <候选池总量>
selected_edl: <实际选用范围>
verified_net_duration: <组接已验净时长>
version: <版本标识>
failure_scope: <如有失败，写具体阶段>
recovery: <只写实际执行过的修复>
```

如果最终结果未知，保留“未知”状态并先读回状态；不要因为一次重试成功就删除失败记录。
