# 传输与恢复

[返回技能](../SKILL.md)

这份参考文档只描述“原文件如何被核验和搬运”的通用流程，不替代具体平台的权限或文件保存说明。

## 推荐顺序

1. 保留原始图像的字节副本，不用页面截图替代原图。
2. 在源端记录格式、像素尺寸和 SHA-256；传输完成后在落地端重新计算并比对。
3. 在复制到 ComfyUI 输入目录前，先打开落地文件检查可读性、方向、颜色、脸、手和关键道具。
4. 记录源引用、落地位置、哈希、尺寸、格式、传输方式和结果。公开记录只保留通用描述，不公开私有文件链接、文件 ID 或机器专属绝对路径。
5. 任何哈希或尺寸不一致都停止后续生成，先恢复文件传输，不要用压缩截图或重新编码“凑一致”。

## Windows 与跨环境边界

Windows 文件保存程序若因 `os.setxattr` 报错，先记录具体错误和已完成的范围。已有同机 WSL 2 Ubuntu 22.04 时，可以按其官方、未修改的文件流程，在 ext 持久目录保留元数据后再复制到 Windows 目标盘；这只是一次观察到的恢复路径，不代表 Windows 不可控，也不代表必须网页登录。

不要为解决传输问题关闭安全检查、伪造元数据、绕过登录或使用 base64 分块技巧。若源端、执行端或复制端的权限不同，分别确认哪一段失败，再选择用户有权使用的受支持文件通道。

## 复现记录字段

```text
source_reference: <公开记录使用的非私有描述>
source_sha256: <值或“未公开”>
source_dimensions: <宽x高>
format: <格式>
transfer_method: <受支持的文件通道>
destination_check: <哈希/尺寸/可读性结果>
failure_scope: <如有失败，写具体阶段>
recovery: <只写实际执行过的修复>
```

如果最终结果未知，保留“未知”状态并先读回状态；不要因为一次重试成功就删除失败记录。
