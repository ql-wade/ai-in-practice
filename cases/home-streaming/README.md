# 家庭串流与成果分享

[返回首页](../../README.md)

## 需求

把 Windows 主机画面送到投影，让家庭设备之间形成可用的串流链路；同时把实践过程整理成短视频、封面和正文，形成能够分享的记录。

## 成果

- 家庭串流方案已实际实施，GPT Agent 参与具体执行，并非只生成方案。
- 已有真实短片制作成 45 秒竖屏视频，配套封面和正文，成功在小红书提交，审核通过，公开笔记可播放。
- 发布过程中的工程经验已整理到 [xhs-agent PR #1](https://github.com/ql-wade/xhs-agent/pull/1)，并合并到提交 `1cd4ed07c04ed6d111a91881db2f50d6755a4e27`。

1080p、60 fps、HEVC 是配置目标。本手记没有长期运行统计或端到端延迟测量，不能据此宣称长期稳定或低延迟。

## 本人和 AI 分工

本人明确家庭使用需求、提供实际环境与素材，并判断公开范围。GPT Agent 辅助实际实施、内容制作、发布操作和状态检查。设备配置结果、素材归因与公开成果需要对照真实环境核查，不能仅凭 AI 的说明认定成功。

## 实施步骤

1. 梳理主机、家庭网络和投影端的连接关系，先确认主机走有线、接收端使用 5 GHz Wi-Fi。
2. 在主机端使用 Sunshine，在投影端使用 Moonlight 建立串流链路；以 1080p60 HEVC 为配置目标。
3. 检查实际画面能否显示和播放。若要评估延迟、断流或长时间稳定性，另行设计测量并记录时长与条件，不能从一次播放推导。
4. 在使用素材前，核对素材来源、归属以及正文中的描述，确认它们讲的是同一件事。
5. 把真实短片整理成 45 秒竖屏视频、封面和正文，检查预览和平台话题。
6. 提交前检查是否已经发布过相同内容；提交后分别读取提交状态、审核结果、公开播放状态。
7. 若需要分享直达链接，在分享当场打开验证。无法确认的链接不写入公开手记。

这些步骤是方法整理，不是逐项性能测试报告。运行实现与后续修复维护在 [xhs-agent](https://github.com/ql-wade/xhs-agent)。

## 验证证据

| 检查对象 | 实际观察 | 能说明什么 |
| --- | --- | --- |
| 真实发布 | 视频已提交，审核通过，公开笔记可播放 | 三个阶段均有结果；不代表所有素材、所有账号或未来发布都成功 |
| 非发布体验测试 | 在云端浏览器完成上传、封面、正文、平台话题和预览播放；没有点击发布，笔记数未变 | 编辑与预览流程可操作；不能当成一次新发布成功 |
| 草稿副作用 | 平台自动留下本地草稿，已记入技能 | 未发布仍可能产生草稿，需要检查副作用 |
| 工程沉淀 | PR #1 已合并，提交见上文 | 可以追溯流程修复；不能替代设备性能或平台发布验证 |

非发布测试不是 CLI 线上测试，也不是 CI 通过。公开仓库不附家庭视频、平台账号和笔记 ID，因此读者无法在这里独立核验该笔记；发布结果属于实践记录，代码改动可通过公开 PR 核查。

## 踩坑修复

- **执行环境选错**：按请求选择本地或云端环境，先检查素材和能力是否在该环境可用，再执行。
- **素材与叙述不一致**：提前检查归因，让视频、封面、正文与来源对应，避免制作完后才发现讲错对象。
- **状态混淆**：等待审批、上传中、明确失败和结果未知是不同状态。先读回状态，再进行次数和范围受限的恢复；未知结果不能直接重试发布。
- **重复提交**：发布前去重，恢复时再次核查既有结果，避免一次不确定反馈产生多篇内容。
- **验证过早结束**：提交、审核、公开播放分别验证，不能把提交成功当成公开可看。
- **链接失效**：分享链接当场检查，无法验证的直达链接不公开。

## 可复用方法和局限

把任务拆成“环境确认 → 素材核对 → 执行 → 状态读回 → 有界恢复 → 成果验证”。每一步留下可观察结果，遇到未知状态先确认再继续。

家庭网络、客户端能力和平台界面都可能不同。这里的设备组合和一次发布结果不构成通用保证；串流性能还需要在自己的环境中测量。本案例公开的是过程与边界，不提供真实媒体素材或第二套发布代码。
