# 本地 Wan 短视频生成与剪辑：重庆火锅抢买单

[返回首页](../../README.md)

> 这是一份本地 AI 视频生成和剪辑的实践记录。场景是马斯克形象与钢铁侠在重庆火锅店抢着买单的 AI 虚构油画，不是现场记录、代言或真人/角色真实行为。

## 需求

在已有本地 GPU 和 ComfyUI/Wan 环境中，把有权使用的参考图做成约 3 秒一段的竖屏图生视频，保留“抢着买单”的动作和结果，再剪辑成带中文字幕、声音和全程 AI 虚构标识的短片。完成标准不是只有文件能解码，还要分别检查技术、视觉一致性和故事是否成立。

## 成果

| 阶段 | 实际结果 | 结论 |
| --- | --- | --- |
| 分段生成与续接 | 先做约 3 秒分段，再用末帧续接；首版 12.25 秒、480×832、16 FPS、196 帧、无声音 | 管线跑通；不代表身份锁定或故事清楚 |
| 剪辑交付 | 9.625 秒、154 帧、AAC 48 kHz 立体声、中文字幕、全程 AI 虚构标识 | 可播放预览；音效电平偏低，声音质量仍待修订 |
| 视觉与故事 | 身份/画风漂移，动作和故事因果不够清楚 | 视觉和故事层未通过；裁剪避脸不是修复 |

因此本案例的交付名称是“预览/待修订”，不是高清成熟产品，也不是验收成片。技术、视觉、故事三层的判定方式见[公开技能的成片验收](../../skills/local-video-director/references/acceptance.md)。

| 环节 | 已观察环境 |

## 本人和 AI 分工

本人确定角色、重庆火锅场景、油画风格、故事目标和公开范围，选择有权使用的参考图，授权本地任务，并指出片尾面貌不一致。AI Agent 实际执行环境检查、模型下载与配置、图生视频任务、剪辑、字幕、音效、编码和抽帧验证。身份、画风、动作因果、手和道具、字幕、声音电平与 AI 标识仍需要按验收标准判断。

## 实施步骤

1. **先核对源图**：在有权使用的原生文件存储中先保存源图，确认格式、像素尺寸和字节 SHA-256；复制后在执行环境重新核对哈希、尺寸和可读性。公开记录不包含私有链接、文件 ID 或电脑专属路径。
2. **先做短样片**：按约 3 秒分段生成，先看每段首、中、尾帧，再决定是否继续；不要把已经漂移的尾帧无限串成长视频。
3. **记录提交检查点**：为每次作业记录源图引用和输入哈希、workflow、prompt ID、种子、模型/量化/版本、原生尺寸、帧数/FPS、输出位置、状态和验收结论。公开案例不填入私有 ID 或无法核实的数值。
4. **剪辑成故事**：从可用片段按“铺垫 → 抢单动作/冲突 → 结果”组织，去掉停滞和重复，统一比例/FPS；不通过裁脸或字幕遮挡来掩盖变脸。
5. **补齐交付信息**：加入中文字幕、可听见的声音和贯穿全片的 AI 虚构标识，检查第一帧、转场和最后一帧。
6. **做三层验收**：技术层检查解码、帧率、音轨、电平、字幕和 AI 标识；视觉层对照原图检查身份、画风、手、道具与边界；故事层确认目标、动作、反应和结果确实发生。

## 踩坑修复

- **Windows 元数据保存报错**：Windows 官方文件保存程序出现 `os.setxattr` 报错。同机已有 WSL 2 Ubuntu 22.04 时，按官方未修改流程在 ext 持久目录保留元数据，再复制到 Windows 目标盘成功。本次只记录这条观察路径，不泛化为 Windows 不可控，也不说必须网页登录。
- **旧 403 的范围**：旧请求的 403 原因不明，不能泛化为所有 Windows 环境都失败，也不能推断一定需要网页登录。应保留“未知”，分别读回源端、执行端和目标端状态。
- **把裁剪当修复**：裁剪可以避开坏帧，但没有恢复身份或风格连续性；后续验收仍按原图逐镜检查。
- **音效存在但电平偏低**：AAC 轨道和非零响度不等于听感合格。重新交付前要测电平并试听全片，不能把“有音轨”写成“声音通过”。
- **重复作业风险**：短样片、prompt ID、种子、模型和输入哈希必须先记录；重连后先查队列/历史与输出，避免重复下载或重复提交未知状态的作业。
